# Bounded guest execution observation

This optional native runtime feature records charge-entry snapshots and actual memory callbacks around an externally supplied tagged PC. It contains no game addresses, instruction decoding or class assumptions. Apply `azahar_guest_execution_observation.patch` after the existing accepted provider patch sequence, including `azahar_guest_write_observation.patch`. The additional patch adds one source to each native executable source list. The compiled frontend remains unchanged and does not create this observer. Existing providers and builds stay immutable; build and validate an isolated native frontend with the affected backend/frontend objects and the new source.

Set `ROOT_PORT_GUEST_EXECUTION_PATH` to an absent file in existing ordinary parent directories, and set `ROOT_PORT_GUEST_EXECUTION_TRIGGER` to an unsigned 32-bit tagged PC. Bit zero selects Thumb; an ARM trigger must be word aligned. Unsigned decimal and `0x` hexadecimal are accepted. Signs, whitespace, trailing characters, partial configuration, existing files, links and invalid limits refuse before capture. No parent directory is created. All seven options unset returns a null observer and leaves the existing unset path active.

| Optional setting | Default | Allowed range |
| --- | ---: | ---: |
| `ROOT_PORT_GUEST_EXECUTION_PREHISTORY` | 16 | 0–256 charged entries |
| `ROOT_PORT_GUEST_EXECUTION_POSTHISTORY` | 32 | 0–512 subsequent charged entries |
| `ROOT_PORT_GUEST_EXECUTION_WINDOW_LIMIT` | 1 | 1–64 windows |
| `ROOT_PORT_GUEST_EXECUTION_EVENT_LIMIT` | 20000 | 1–100000 output records before footer |
| `ROOT_PORT_GUEST_EXECUTION_BYTE_LIMIT` | 16777216 | 8192–67108864 bytes including footer |

The shared observer collects a global ring of charged entries across both CPUs. It intentionally evicts entries older than the selected prehistory extent. A matching charge starts a window containing the currently retained entries, the attempted trigger entry and the selected number of later charge entries. Matching triggers inside an open window are counted without extending it. The next charge-entry boundary closes a full window before its scheduling admission. Its raw address, span, context, RAM prefix and pre-admission snapshot are retained as closing evidence, with admission explicitly unobserved. After the selected number of full windows, collection disarms; later triggers and callbacks are outside the declared scope. No trigger is successful only as a zero-window observation, explicitly reported by the footer. Capture ending with an open window emits its available records with an incomplete window/footer and makes an otherwise successful capture return failure. Even posthistory zero requires a later boundary to delimit the trigger entry's callbacks.

Windows are written when closed, with records sorted by observation order. `output_sequence` counts unique emitted records. `observation_order` and callback completion order identify chronology inside the shared observation invocation; overlapping prehistory can repeat a historical observation in another window. Charge metadata labeled `by_window_emission` contains admission results known when the buffered window is emitted. The separate `admission` record preserves the actual ordering. The header, context registrations, window boundaries and records share the output event/byte limits. A 4096-byte footer reserve prevents a bound refusal from silently becoming successful truncation. Callback count is capped at 32 per charge, record count at 128 per charge, retained record storage at 16384 records, contexts at eight and distinct page-table ownership identities at 4096. Unexpected omissions, allocation/IO errors, bound excess and memory-operation failures make the footer incomplete. Exception text is limited to 1024 bytes and flags any text truncation.

Charge records contain the raw charged address, instruction-set state, span, supplied timing value, CPU/backend identity and pre-admission registers. Snapshots include all exposed general, floating and coprocessor registers, raw condition fields, CPSR/control, FPSCR/FPEXC, TLS, exclusive context, timer values, scheduled instruction count and available dispatcher state. Coprocessor capacity follows the clean provider's `CP15_REGISTER_COUNT`, which is 84 in the sealed Azahar headers. The backend checks that its register array and snapshot array have identical types and extents at compile time, then copies and emits every coprocessor slot without truncation. A span of one and successful admission can provide a precise pre-instruction **candidate** for a matching callback. A span other than one, rejected admission, context break, unavailable instruction RAM or mapping disagreement remains unproven. The RAM prefix is four raw bytes, with tagged Thumb addresses normalized only by removing bit zero. Thumb length is not decoded. Misaligned ARM addresses are invalid and never rounded to another instruction.

Read callback records retain the value returned by the one original MemorySystem read. Write callback records retain the supplied source bytes and sampled destination before/after the one original write. The read result is not assigned to a translated register until the original caller resumes. Callback entry can already reflect translated pre/post-index writeback. The after-callback snapshot is immediately after that memory operation, not full architectural post-instruction completion or exclusive-store success. Diagnostic failures never retry or replace a memory operation; if an original operation raises, its exception takes precedence over logging failures. If logging fails after a successful operation, the capture fails after that operation. With the existing writer also enabled, that failure can make its enclosing writer record conservative about return success; failed observation captures are excluded.

All diagnostic RAM sampling validates every requested byte against the actual `MemorySystem::GetCurrentPageTable()` pointer array and `PageType::Memory`, then reads only those direct bytes. No extra guest MemorySystem read, MMIO, watchpoint, rasterizer or flush operation occurs. Page tables receive bounded monotonic identities using shared ownership control blocks, with weak ownership retained to prevent host-address/control-block reuse from producing an identity match. Changes in the actual table and unavailable/changed sampled instruction or destination mappings break the context segment. Backend `SetPageTable` is recorded separately from the actual MemorySystem table. There is no provider-wide remapping hook: unobserved in-place remaps outside sampled pages, remap-and-restore between samples, concurrent RAM changes, HLE/direct writes and accesses bypassing callbacks remain coverage gaps. A completed stream does not establish uninterrupted coverage of every guest operation.

Run entry/return, dispatch return, SVC entry/return/exceptions, scheduling yield, reschedule requests, context load, external register/status setters, exclusive resets, cache invalidation and unsupported interpreter requests are explicit boundary/gap records. A next charge is an observed state boundary, never proof of original instruction retirement or a completed gameplay update. The explicit context registration maps the new observer identity to the accepted writer observer's context identity; callback snapshots retain that writer's unchanged generation and write ordinal. Join both streams only within the same recorded invocation and registered context, using charge/generation/ordinal and byte/table evidence. Numeric coincidence, saved LR, or a pointer value alone establishes no call ancestry, publication ownership, actor/player identity, lifetime, update phase or Section 7 semantic state.

The frontend gives both CPUs one shared observer and finishes both configured streams against the real headless capture result, even if one footer fails. Root must independently build the isolated source closure and verify unset/enabled original-movie replay, both zero-fallback CPU reports, original instruction bytes, refusal/bound behavior and input/GPU/PICA/pixel/audio/tick preservation. This source-only implementation has not been compiled or executed by its implementation helper and claims no milestone completion.
