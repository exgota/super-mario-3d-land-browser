Verified on 2026-10-01 with Apple Clang 21.0.0, C++20, AddressSanitizer and UndefinedBehaviorSanitizer. `runtime/AssetReader.cpp` remains outside Game/al and the ARMCC matching build. Its CGFX catalog now includes resource-local vertex attributes, index streams, serialized primitive topology, inline vector fields, raw skeleton records, model-local mesh/material identities, resource-local texture references, raw image headers/payload extents, bounded RGB565 integer storage, ETC1 compressed fields and two draw-transfer interfaces. It does not apply a skeleton, shape or world transform, interpret material state or render a model.

The owner's selected files use CGFX revision 0x05000000. Their CMDL shape lists point to SOBJ records with flags 0x10000001. The documented count, self-relative pointer and stride fields lead to 0x40000002 interleaved vertex groups, 0x40000001 component declarations, face groups and index descriptors. Metadata stays inside DATA; vertex and index buffers stay inside the IMAG payload. The reader bounds those regions before traversal and limits decoded components by the source file size.

The public [CGFX description](https://www.3dbrew.org/wiki/CGFX) establishes the record layout. Its compact scalar-type table differs from this owner's variant, which stores OpenGL scalar enums. The [Khronos registry header](https://github.com/KhronosGroup/OpenGL-Registry/blob/main/api/GLES/gl.h) establishes those enum values. The reader handles float32, signed/unsigned byte and signed/unsigned short components. Each attribute retains its raw component words, multiplier bits and scaled float32 bits. Semantic IDs remain numeric, including unresolved semantic 2.

The RGB565 reader exposes little-endian packed words, source byte offsets, logical storage coordinates and integer R5/G6/B5 channels. The primary [SMDH tiling description](https://3dbrew.org/wiki/SMDH) establishes Morton order within each 8 by 8 tile. The [GPU transfer description](https://www.3dbrew.org/wiki/GPU/External_Registers) independently supports sequential tile storage and the RGB565 byte/channel arrangement. The [GPU texture-register description](https://3dbrew.org/wiki/GPU/Internal_Registers) establishes contiguous mip data and format 3; the official [OpenGL ES 2.0 specification, section 3.6](https://registry.khronos.org/OpenGL/specs/es/2.0/es_full_spec_2.0.pdf) establishes the 5/6/5 component bit positions. Tile rows advance before the next tile row; the low three x/y bits interleave with x in even positions. This is a public-format storage interpretation, not a comparison with GPU sampled output.

All eight owner RGB565 images have eleven mip levels in total, each at least 8 by 8 with dimensions divisible by eight. Halving each dimension per successive level and consuming two bytes per texel covers all 75,648 serialized bytes exactly, with no padding or leftover bytes. The ETC1 reader exposes the resource-local 64-bit compressed word as hexadecimal, each 4 by 4 block's storage coordinates/source offset, mode and partition bits, two table codewords, endpoint codewords and sixteen selectors. The public CGFX description independently establishes the 3DS little-endian word variant and 8 by 8 tiles. Four blocks within each tile advance through the upper-left, upper-right, lower-left and lower-right storage quadrants; tiles advance across x before y. Selector bits use column-major bit positions, while the reported selector array traverses logical rows. These coordinates imply no display orientation.

In individual mode, `endpoint_codewords` and `secondary_codewords` preserve the two four-bit triplets. In differential mode, they preserve the five-bit base and unsigned three-bit delta codewords, with a separate signed delta triplet. Adding each signed delta checks the unexpanded [0,31] domain. Invalid domains retain every raw field and have explicit block/image status; they produce no color. The reader performs no endpoint replication, table lookup, modifier application or color expansion. Reproduce inspection after local extraction:

```sh
. ./development_environment.sh
clang++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -fsanitize=address,undefined -g runtime/AssetReader.cpp -o build/runtime/asset_reader
python - <<'PY'
import json
from pathlib import Path
import subprocess
directory = Path('data/runtime/romfs')
manifest = json.loads((directory / 'world_one_extraction.json').read_text())
paths = [str(Path('data/runtime/extracted') / item['path']) for item in manifest['files']]
with (directory / 'native_mesh_report.json').open('w') as report:
    subprocess.run(['build/runtime/asset_reader', *paths], stdout=report, check=True)
PY
```
