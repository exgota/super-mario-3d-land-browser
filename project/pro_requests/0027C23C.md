## Attempts and reason for stall

1. Nine scalar snapshots, explicit identity stores, scalar adjugate snapshots and stores.308 bytes under each compiler. The compiler reuses determinant products in later cofactors, raises the VFP save frame before the zero branch, scatters input loads and output stores, and uses VCMP/VMRS rather than the target's word comparison.
2. Aggregate input snapshot, aggregate identity and runtime aggregate result.288-byte function plus a separate36-byte identity constdata object under each compiler. The data relocation triggers the canonical-only closure gate on scratch inputs, so no final byte comparison occurred. We did not bypass provenance or invent an address for the source identity.
3. Scalar snapshots, faithful IEEE word test for the two observed zero signs, and runtime aggregate result without constant identity data.316 bytes under each compiler, still oversized. No inline helper, barriers, volatile fields or instruction substitutes were introduced.

The paired compiler function bytes and extra constant bytes are mechanically equal for each form. This does not turn a size/gate rejection into a full comparison. A missing live provenance-template path during root's clean rebuild prevented one script from starting a compiler; environment_retry.json records using the frozen canonical command from form1 thereafter. No optimization flags change.

The target coordinates fixed VFP register batches; current ordinary C++ forms do not. Its inheritedfa metadata and coordinated instruction pattern suggest manual scheduling but do not establish the original source language. Further progress needs an independently supported API/translation-unit structure or another source-level explanation. We stopped rather than fabricate a helper solely for register allocation. Functional equivalence, exceptional floating behavior and game integration remain unverified.
