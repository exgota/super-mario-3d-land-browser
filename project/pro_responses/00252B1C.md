## 1. Fused compare/erase step with reference-returning append (roughly 10%)

Unlike variant 6 (precomputed slot passed to an erase-only helper), slot construction, comparison, last-element replacement, and the returned loop bound share one helper, so ARMCC can optimize a whole iteration before inlining it. Intended: cancelAt's early return becomes ldrne r2, [r3, #4] then branch to the latch; the decrement result feeds the latch compare; extend() returns an element reference, separating count reservation from the actor store (an opportunity, not an ordering guarantee).

```cpp
#include <Execute/alExecuteRequestKeeper.h>

namespace al
{

struct ExecuteRequestQueue
{
int mOpaque00;
int mSize;
LiveActor** mBuffer;

int cancelAt( int index, const LiveActor* actor )
{
LiveActor** buffer = mBuffer;
LiveActor** element = buffer + index;
if ( *element != actor )
return mSize;

int lastIndex = mSize;
if ( index < lastIndex )
{
--lastIndex;
*element = buffer[ lastIndex ];
}
return --mSize;
}

void cancel( const LiveActor* actor )
{
int limit = mSize;
for ( int index = 0; index < limit; ++index )
limit = cancelAt( index, actor );
}

bool contains( const LiveActor* actor ) const
{
bool found = false;
for ( int index = 0; index < mSize; ++index )
{
if ( mBuffer[ index ] == actor )
{
found = true;
break;
}
}
return found;
}

LiveActor*& extend()
{
++mSize;
return mBuffer[ mSize - 1 ];
}
};

{

else if ( requestType == 1 )
opposingQueue = _0[ 0 ];

if ( !requestQueue->contains( actor ) )

}
```

Assumption: all helpers inline, no surviving calls or stack temporaries. Risk: flattened back to variant 6's form, or the slot load folded into indexed addressing.

## 2. Representation-copy slot proxy (roughly 7%)

Reads/writes the pointer representation through fixed-size memcpy so ARMCC may keep address-based copies through alias analysis and lower them late, preserving the early slot address, the post-replacement count reload, and a different allocation. A compiler-phase hypothesis; 791 behavior untested. The append returns a one-pointer proxy by value. The temporary in set() avoids overlapping memcpy when the removed entry is last.

## 3. Selective volatile views with explicit count snapshots (roughly 5%)

Strongest access-order experiment, weakest claim about the original API. Field declarations stay ordinary; only this function's queue views and opposing-slot accesses are volatile. Requests: one initial opposing count read; one opposing buffer read per iteration; a nonmatch count read; separate match-path and post-replacement count reads; no reread after storing the decrement; one selected count read; selected buffer read only for a positive count; another selected buffer read after storing the incremented count. newSize is returned from a local; append takes the new count as an argument.

```cpp
#include <Execute/alExecuteRequestKeeper.h>

namespace al
{

struct ExecuteRequestQueue
{
int mOpaque00;
int mSize;
LiveActor** mBuffer;

int cancelAt( int index, const LiveActor* actor ) volatile
{
LiveActor* volatile* buffer = mBuffer;
LiveActor* volatile* element = buffer + index;
if ( *element != actor )
return mSize;

int lastIndex = mSize;
if ( index < lastIndex )
{
--lastIndex;
*element = buffer[ lastIndex ];
}

int newSize = mSize - 1;
mSize = newSize;
return newSize;
}

bool contains( const LiveActor* actor, int count ) const volatile
{
bool found = false;
if ( count > 0 )
{
LiveActor** buffer = mBuffer;
for ( int index = 0; index < count; ++index )
{
if ( buffer[ index ] == actor )
{
found = true;
break;
}
}
}
return found;
}

void append( LiveActor* actor, int newSize ) volatile
{
mSize = newSize;
LiveActor** buffer = mBuffer;
buffer[ newSize - 1 ] = actor;
}
};

void ExecuteRequestKeeper::request( LiveActor* actor, int requestType )
{
volatile ExecuteRequestQueue* requestQueue = _0[ requestType ];
volatile ExecuteRequestQueue* opposingQueue = 0;
if ( requestType == 0 )
opposingQueue = _0[ 1 ];
else if ( requestType == 1 )
opposingQueue = _0[ 0 ];
else if ( requestType == 2 )
opposingQueue = _0[ 3 ];
else if ( requestType == 3 )
opposingQueue = _0[ 2 ];

int opposingSize = opposingQueue->mSize;
for ( int index = 0; index < opposingSize; ++index )
opposingSize = opposingQueue->cancelAt( index, actor );

int requestSize = requestQueue->mSize;
if ( !requestQueue->contains( actor, requestSize ) )
requestQueue->append( actor, requestSize + 1 );
}

} // namespace al
```

Risk: access constraints don't fix coloring, predication, or arithmetic placement; ARMCC may merge the two mutually exclusive count reads.

## If all three miss, classify the first structural divergence

1. Slot formation and selected-queue allocation:

```
ldr ip, [r3, #8]
add r2, ip, r0, lsl #2
ldr r4, [r2]
cmp r4, r1
```

An indexed actor load with a later slot-address calculation = the address hypothesis didn't survive. Selected queue still in ip = examine slot/buffer interference; don't try declaration moves or `register`.

2. Every opposing count access: nonmatch reload at 0x252B74, match bound at 0x252B7C, post-replacement reload at 0x252B94, decrement store at 0x252B9C compared at the latch. An extra reload after the store is a different failure from losing the nonmatch reload; candidate 3 separates these.

3. Append scheduling vs arithmetic:

```
add r0, ip, #1
str r0, [r5, #4]
ldr r3, [r5, #8]
mvn r2, #3
add r0, r2, r0, lsl #2
str r1, [r3, r0]
```

Buffer load before count store = scheduling miss. Old count used directly, separate subtraction, new count elsewhere, or a completed element address before the store = distinct arithmetic/allocation misses.

4. Reject structural overhead first: unrolled search, surviving boolean, helper/copy calls, spills, changed save set, PC-relative loads. The pool must stay empty. 220 bytes alone is only an intermediate observation.
