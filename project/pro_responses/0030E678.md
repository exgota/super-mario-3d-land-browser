## 1. Split three-component product and scalar

Hypothesis: represent the persistent intermediate as a three-component vector plus a separate negative-dot scalar. This gives the compiler a different scalar-replacement problem from both four independent scalar declarations and the packet's four-field quaternion assignments.

The intended allocation is the vector product in s0–s2, with the scalar in s3. That is a hypothesis about aggregate lowering and value ordering—not a C++ guarantee. The existing Vector3f constructor initializes its three public fields directly, so this needs no shared-header extension.

```cpp
namespace
{

inline void rotateFrontSplit( sead::Vector3f& vector, const sead::Quatf& rotation )
{
const sead::Vector3f product(
rotation.y * vector.z - rotation.z * vector.y + rotation.w * vector.x,
rotation.z * vector.x - rotation.x * vector.z + rotation.w * vector.y,
rotation.x * vector.y - rotation.y * vector.x + rotation.w * vector.z );
const float scalar = -rotation.x * vector.x - rotation.y * vector.y - rotation.z * vector.z;

vector.x = product.x * rotation.w - product.y * rotation.z + product.z * rotation.y - scalar * rotation.x;
vector.y = product.y * rotation.w + product.x * rotation.z - product.z * rotation.x - scalar * rotation.y;
vector.z = product.y * rotation.x - product.x * rotation.y + product.z * rotation.w - scalar * rotation.z;
}

} // namespace
```

Header changes: exactly the complete common diff above; no others.

Compiler behavior targeted: constructor-argument lowering and scalar replacement of a three-member aggregate, followed by a distinct scalar definition. Unlike the frozen quaternion-record form, there is no fourth aggregate member whose assignment position competes with product.y.

First diagnostic: look at 0x0030E6C4 and 0x0030E6CC. The useful result is the negative-dot chain in s3 and the product.y chain in s1, while preserving the existing instruction positions. Then check whether the input assignments also become rotation.x→s9, rotation.w→s7, and vector.z→s6. Those input changes matter just as much as fixing the two product registers.

## 2. Four accumulators expressed in three phases

Hypothesis: expose the target's four interleaved accumulator chains explicitly, rather than presenting four completed expressions to the optimizer.

This form separates the initial multiplications, subtract-accumulations, and final accumulations. Its arithmetic statement order follows the target's x, w, z, y issue pattern, while the named accumulators are introduced in logical x, y, z, w order. The declaration order alone does not bind registers; the substantive change is the creation of partial accumulator values in separate full expressions.

```cpp
namespace
{

inline void rotateFrontPhased( sead::Vector3f& vector, const sead::Quatf& rotation )
{
float px;
float py;
float pz;
float pw;

px = rotation.y * vector.z;
pw = -rotation.x * vector.x;
pz = rotation.x * vector.y;
py = rotation.z * vector.x;

px -= rotation.z * vector.y;
pw -= rotation.y * vector.y;
pz -= rotation.y * vector.x;
py -= rotation.x * vector.z;

px += rotation.w * vector.x;
pw -= rotation.z * vector.z;
pz += rotation.w * vector.z;
py += rotation.w * vector.y;

vector.x = px * rotation.w - py * rotation.z + pz * rotation.y - pw * rotation.x;
vector.y = py * rotation.w + px * rotation.z - pz * rotation.x - pw * rotation.y;
vector.z = py * rotation.x - px * rotation.y + pz * rotation.w - pw * rotation.z;
}

} // namespace
```

Header changes: exactly the complete common diff above; no others.

Compiler behavior targeted: accumulator recognition, intermediate-value numbering, and lifetime/coalescing decisions before final scheduling. The form also postpones every use of rotation.w to the final phase, consistent with the target loading it at 0x0030E6D0. The goal is to change allocation without disturbing the schedule that already agrees.

First diagnostic: the four final product values must still be built using the same initial vmul/vnmul and vmla/vmls chains, with no standalone additions or extra moves. If this collapses to the frozen 55-byte diff unchanged, ARMCC has likely canonicalized the phased expressions back to the same representation; declaration-order changes alone would then be a poor next experiment.

## 3. Return-by-value product constructed from four expressions

Hypothesis: change how the quaternion intermediate enters the caller by producing it through an inlined return-value construction. This differs from the packet's default-constructed Quatf followed by four assignments.

The actual Quatf has only four public scalar members, an empty default constructor, and the direct four-argument constructor used below. No quaternion-library additions are required.

```cpp
namespace
{

inline sead::Quatf makeFrontProduct( const sead::Quatf& rotation, const sead::Vector3f& vector )
{
return sead::Quatf(
rotation.y * vector.z - rotation.z * vector.y + rotation.w * vector.x,
rotation.z * vector.x - rotation.x * vector.z + rotation.w * vector.y,
rotation.x * vector.y - rotation.y * vector.x + rotation.w * vector.z,
-rotation.x * vector.x - rotation.y * vector.y - rotation.z * vector.z );
}

inline void rotateFrontReturned( sead::Vector3f& vector, const sead::Quatf& rotation )
{
const sead::Quatf product = makeFrontProduct( rotation, vector );

vector.x = product.x * rotation.w - product.y * rotation.z + product.z * rotation.y - product.w * rotation.x;
vector.y = product.y * rotation.w + product.x * rotation.z - product.z * rotation.x - product.w * rotation.y;
vector.z = product.y * rotation.x - product.x * rotation.y + product.z * rotation.w - product.w * rotation.z;
}

} // namespace
```

Header changes: exactly the complete common diff above; no others.

Compiler behavior targeted: constructor-argument evaluation, return-object elimination, and scalar replacement across the extra inline boundary. Constructor arguments do not impose left-to-right evaluation, and an inlined helper does not impose an ABI register assignment; this candidate relies on ARMCC's lowering choices, not on either of those false assumptions.

First diagnostic: the intermediate must disappear into registers. An additional helper call, stack-resident product, copy sequence, or larger frame makes this form a regression. A useful miss would preserve the 704-byte interval and existing schedule while producing a different product/input-register mapping.
