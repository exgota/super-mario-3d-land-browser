# Independent data evidence for the emitter child update

This note proposes the neutral external identity `dat_00430A88` for the previously unmapped **48-byte BSS object at 00430A88..00430AB8**. It changes no map row, boundary, Type, source body, initializer or executable. It is a prerequisite proposal, not canonical acceptance. The original EU executable is independently verified as SHA-256 `e1d7e188ff88467df776c17cec45c44857fadf5b699944baa8cddcae7d939e64`.

The evidence is independent of a candidate relocation or desired match. The existing mapped initializer `__sti___14_seadMatrix_cpp`, starting at 003834C8, loads zero into s0 at 003834CC and one into s1 at 003834D0. At 00383580 its PC-relative load reads the literal at 003837F4, whose address value is 00430A88. Instructions 00383584..003835B0 write exactly twelve binary32 elements to that object. Ones are stored at offsets 0, 0x14 and 0x28; the other nine words are zero. The resulting row-major 3×4 matrix is the identity affine transform. The preceding initialized 48-byte matrix starts at 00430A58; the next separately initialized float matrix starts at 00430BB8. The later double-matrix initialization begins its next object at 00430AB8. These explicit writes and neighboring starts support this object's exact 48-byte extent without splitting an existing map row.

Exheader fields independently put the data segment at 003E1000, with initialized size 000129D4 and BSS size 0003D684. 00430A88 lies in that BSS extent. The linked identity is not a read-only literal array stored in the original executable. The reconstruction imports the object; it does not replace its reads with twelve C++ constants or an absolute-address dereference.

The proposed root's independent consumer evidence is 002ECC64..002ECC8C: after copying a trail sample's position, it passes current sample+0x10 as r0 and the 00430A88 object as r1 to the existing mapped Matrix34 copy at 0027C18C. That callee loads all twelve floats from r1 before storing twelve floats through r0. The alternate branch passes the state matrix at state+0x48 to the same callee. Thus the data object's matrix role is supported by both initialization and use.

The existing clean `sead::Matrix34<float>::ident` declaration suggests a plausible public identity, and the map already identifies the enclosing initializer as sead matrix initialization. This note conservatively proposes only a neutral address name. Main owns any public-name decision and any separately reviewed map addition. The private source declaration uses the existing clean `nn::math::MTX34` field definition, token-identical to `Math/seadMatrixConversion.cpp`. No shared header changes are needed.

Two other imports already have complete original rows: 003EFA14..003EFA18 and 003EFA18..003EFA1C. The proposed root loads a pointer from each, indexes it by a masked 9-bit counter multiplied by twelve, and reads three floats. These observations support pointers to 512-entry VEC3 arrays for this caller's indexing contract. They do not recover the initialization, distribution or mathematical identity of those tables. The replay uses explicit synthetic table contents, not replacement game assets.

The existing 003EF914..003EF918 row is a manager pointer, consistently with the separately reconstructed effect resource initializer and emitter command update. In this root, calls to the original allocators at 0021FFCC and 002E5984 receive that pointed-to manager. The allocators access the particle pool at manager+0x420 and trail pool at manager+0x424, with strides 0x124 and 0x2688 respectively. This proposal adds no implementation or alias for either allocator.

Both failures are retained. They are not repaired by changing the checker or silently adding the proposed row. The whole-root execution diagnostic alone binds this independently evidenced external import to its observed address.
