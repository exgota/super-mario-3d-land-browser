## Independent identity and layout evidence

This root initializes allocator-backed selector storage and three required plus one optional value arrays. It is distinct from neighboring `0x00230794`'s resource-tag construction dispatcher. The names are descriptive; no proprietary SDK identity is assumed.

Five direct callers are found in the verified executable: `0x00231CF8`, `0x0029FD60`, `0x002A864C`, `0x002AF104`, and `0x002B0DCC`. Their enclosing intervals are respectively `0x00231C58..0x00231EB4`, `0x0029FC50..0x0029FFFC`, `0x002A85AC..0x002A874C`, `0x002AF01C..0x002AF1B8`, and `0x002B0D2C..0x002B0FB0`. Each nearby sequence allocates 0x68 bytes, calls constructor `0x0023062C` with resource/opaque-context/allocator, then calls this root. The callers test the returned sign bit and invoke the object's destructor and allocator free on failure.

The independent constructor stores allocator at +4 and resource at +8, initializes arrays at +0x0C/+0x20/+0x30/+0x40/+0x50, stores the opaque context at +0x1C, and installs vtable `0x003D86F8`. Its first slot is original destructor `0x002B3E7C`. That destructor independently visits the same five arrays in reverse order, resets each end to begin, and conditionally calls allocator vtable+0x0C. These observations support the storage layout without using this root as its sole source. The C++ Storage struct describes the prefix the root uses, not the complete 0x68-byte object.

Each array prefix contains allocator, begin, end, and capacity/flags words at +0/+4/+8/+0x0C. Capacity occupies the low 30 bits. Allocation uses virtual slot +8 with size count×4 and alignment 4. On success, a temporary array is exchanged with the destination; the previous array is cleared and freed when both its allocator and begin are nonzero. The old high flag bits do not suppress this free. Each value array is then resized to signed resource+0x10. The generic growth branch uses alignment 32 only when the array has an allocator and its high two flag bits equal 1; otherwise the requested size is clamped to capacity. A failed initial allocation returns `0x80000000` immediately, retaining completed earlier state and allocations. Success returns zero; optional=false leaves the final array untouched.

Resource+0x18 is a signed selector count. Its +0x1C field is a signed displacement relative to that field, resolving an array of selector integers. Positive selector counts require a valid resolved array. All twelve static guards are visited before each selection, even for an invalid selector. Original `0x0028A998` is a 28-byte non-atomic guard operation: zero becomes one and returns one; any nonzero word returns zero. The outer test checks bit 0, so other nonzero even guards still call this routine and skip construction.

## Replay domain, exclusions and final checks

Fixtures cover each valid selector, four invalid selectors, zero/multiple/repeated selectors, positive and negative relative displacements, values 0/1/2/3/4/5/7, optional on/off, cold/hot/nonzero-even/mixed guards, old arrays with zero or different allocators, allocation failure at each initial allocation, and three repeated calls. Reentrant free models additionally exercise grow, clamp, shrink and no-allocator branches for each value array. Lifecycle fixtures use original construction and destruction, including destruction after partial failure. An independent descriptor-address oracle checks successful selector outputs, in addition to original-versus-candidate comparison.

Allocator callbacks are deterministic synthetic models, including explicit allocation-failure injection, poisoning of freed fixture memory and the stated reentrant metadata mutations. They do not establish any actual retail heap behavior. No original descriptor computation method is replayed as part of this root validation. Concurrent guard initialization, asynchronous observers, exceptions, invalid pointers, cyclic/overlapping objects, arbitrary signed-overflow inputs, arbitrary reentrant callbacks, real resource datasets, and gameplay are outside this evidence. Entire fixture memory and descriptor padding are compared; only private stack scratch/register caller-clobbered state are excluded.
