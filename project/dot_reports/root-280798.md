The root stores component type 1402, index type 1401 or 1403, and builds an

triangle. The behavior is preserved even for the diagnostic zero-index case;
this is not input validation. The final index allocation uses one or two bytes
per index. RAM buffers copy directly; other memory kinds queue copies and run
the synchronization sequence. Temporary loaded data is finally freed.

## Replay model and limits

The harness loads the untouched private executable into an ARM1176 Unicorn CPU,
enables VFP, and substitutes the separately linked committed-source root for the
candidate side. The original `__rt_memcpy`, its tail path `__aeabi_memcpy4`, and
`nngxGetAllocator` execute their actual retail instructions on both sides. The
allocator pair is initialized to an explicit deterministic test callback.

Resource loading supplies generated serialized blobs; heap/buffer allocation,
free, GPU queue-copy, cache flushing, and synchronization are explicit models.
GPU queue-copy immediately copies bytes; no GPU scheduling, cache coherence,
resource archive, allocator implementation, or real graphics execution is
claimed. External model returns poison caller-saved integer and VFP registers,
so an accidental dependence on preserved volatile registers is exposed.

The main cases cover all nine categories; zero, constant, and interleaved streams;
both index widths; all 48 axis permutation/negation combinations; translation and
mirroring; three memory kinds; absent/empty/sparse/dense occupancy; filter-disable
flags; zero/negative query sizes; empty segment lists; and a two-segment storage
probe. The header records the first inline segment; the multiple-segment case
observes the original contiguous memory writes and is not a claim of unrestricted
C++ array capacity. A zero-index filter diagnostic follows the original minimum
three-index behavior using addressable surrounding test memory; it does not
establish safety for malformed resources.

The extension covers all 27 combinations of attribute counts 0..2, missing
resource/allocation outcomes for each category, finite/subnormal/signed-zero
scale cases, and FPSCR 0, FZ, DN, FZ|DN, and all three nondefault rounding modes.
Conversions in the ordinary numerical cases stay in the signed-short range.
NaNs, infinities, out-of-range conversion, arbitrary aliasing of resource and
loaded data, unbounded segment counts, hostile tables, allocation failures after
buffer creation, and malformed-resource memory safety are not established.
The float component-type conversion branch is retained but not dynamically
covered under the distinct-input-buffer model.

Each run is bounded at 300,000 instructions and 2 MiB of generated-data memory;
all reported runs return, with a maximum of 6,403 instructions. This is not a
proof of termination outside the tested inputs or for modeled synchronization
calls. The comparison covers 0x800 resource bytes, every generated allocation's
requested bytes, and the complete ordered external event trace. Temporary stack
bytes, unspecified return r0, and private runtime-copy register clobbers are not
compared. Stack pointer, r4..r11, and d8..d15 are checked at return. Final FPSCR is
compared explicitly in the 315-case extension; all agree.
