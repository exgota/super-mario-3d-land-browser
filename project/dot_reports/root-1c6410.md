## Independent purpose, layout and callee evidence

The caller at `0x001C0C0C` allocates 0x480 bytes, conditionally invokes the root at `0x001C0C1C`, and stores the returned pointer at its own +0x18. The root creates Japanese-named stage default light records, looks for `ObjectData/LightDataArea` and `ObjectData/LightDataMap`, enumerates `/`, accepts names containing `.byml`, loads BYAML records, sorts them and constructs two fallback lights. This establishes lighting-data initialization without claiming the original director class name.

Recovered fields are:

| --- | --- |
| 0x000 / 0x004 | Stage area-light record / map-light record |
| 0x008 / 0x018 | 16-byte rings: buffer, capacity, head, count |
| 0x028..0x038 | Five zeroed, otherwise unnamed pointers |
| 0x03C | Fixed ring header; 128 eight-byte entries at 0x04C..0x44B |

| 0x474 / 0x478 / 0x47C | Two fallback lights and a zeroed pointer |

Area records are 0x128 bytes: name, interpolation frames, three 0x60-byte light parameters. Original `0x001C4F64` independently reads `Name`, `Interpolate Frame`, `Player Light`, `Obj Light` and `MapObj Light`. Map records are 0x64 bytes: name plus one light; original `0x001D4B5C` reads `Name` and `Light Param`. Original `0x0024E0B8` names Ambient, Diffuse, Specular0, Specular1, ConstantColor5, Direction and IsCameraFollow fields. The original constructors, copy constructor and assignment at `0x0024DA80`, `0x0024E054` and `0x0024DAFC` independently fix the 0x60-byte record, its 23 float words, boolean at +0x5C and untouched tail padding.

Both ring sorts intentionally use `front()` and `back()` as a half-open range: the final populated record is excluded. The retained comparator helpers sort the preceding records by descending name. The depth argument passed to the partition helper is the pointer distance in records. The 16-element final-insertion threshold and the original area/map helper call boundaries are preserved. This surprising last-record behavior is verified by an independent output oracle, not silently corrected.

The two fallback records retain their five colors, direction and camera-follow flag. The first uses zero ambient/diffuse/constant color, half-gray specular colors with zero alpha, direction (0,0,1), false. The second uses ambient (.23,.22,.178,1), diffuse (.255,.254,.213,1), two (.5,.5,.5,1) specular colors, constant (.2,.2,.155,1), direction (-1,-1,-.7), true. Original color clamping and the original light constructor execute during replay.

## String address point, without an ownership claim

The existing map contains a 20-byte unnamed row `0x003D7ABC..0x003D7AD0`. That is an existing map interval, not proof of a complete C++ table allocation. The root installs **address point 0x003D7ABC**, sets a buffer pointer and capacity 128, clears the first/last storage bytes and dispatches slot +8 before reading the buffer.

Independent original code establishes the same descriptor behavior:

- `0x00243A7C..0x00243A9C` sets storage at descriptor +0xC, capacity 128 and address point 0x003D7ABC; `0x00243AA8..0x00243AB4` dispatches slot +8
- The variadic constructor `0x0028CB38` calls storage initializer `0x0028AEA8`, then installs the same address point at `0x0028CB50`
- The table's slot +8 points to `0x0039E0E4`, which writes a zero at buffer + capacity - 1

The source represents this observed prefix explicitly and declares an unsized raw extern. It does not alias a generated `FixedSafeString<128>` table, claim an owner from capacity, combine neighboring rows or assert whole-table bounds. The initial typed ownership assumption is withdrawn. Further class/table reconstruction needs independent complete initializer/consumer bounds and remains separate work. The same caution applies to the raw global read at 0x003E23B8: its whole owning object is unclaimed.

## Whole-root behavioral validation

The final ordinary ARMCC section and original root each run on an ARM1176 Unicorn CPU with the same controlled memory and registers. **130 paired cases pass: 129 returning pairs and one paired fault**, with **14,253 independent semantic assertions per implementation**. All 762 original code addresses are visited across the suite; this includes predicated instruction addresses and is not a claim that every path or predicate outcome was covered.

Returning pairs compare the returned pointer, all 0x480 bytes of director state, each allocated block including cookie and untouched padding, and ordered boundary interactions. Pointers to source-local literal strings are compared by their string contents; every other retained pointer/byte is compared directly. All returning cases preserve SP, R4–R11 and D8–D15. Independent assertions check ring counts, descending order of the half-open sort range, unchanged final record, interpolation values, nested light fields and every fallback light field.

The suite covers both archives separately and together; absent archives and null resources; zero/negative directory counts; 1, 2, 3, 16, 17, 18, 31 and 40 records; forward, reverse and shuffled names; 1, 3, 18 and 33 records with nested lighting fields; filename filtering; six malformed/null BYAML cases; six allocation-failure positions for area, map and combined loads; both creator-null cases; and several initial-memory sentinel patterns.

Twenty named original callee entries execute, including area/map constructors, array-entry initialization, actual BYAML construction/readers and nested light parsing, light/color construction/copy/assignment, string termination and both original partition/insertion-sort algorithms. The 130-case run records 220 calls to the original nested light parser. This is **whole-constructor replay with real original callees inside explicitly modeled boundaries**, not an arithmetic-only slice.

Modeled boundaries are ordinary allocation, current-heap lookup, the two graphics-object creation entry points, resource existence/lookup, directory enumeration and file retrieval. Four global default light records are controlled inputs copied by real original constructors; their production initialization is not reconstructed. Graphics object internals, filesystem/archive behavior, allocator behavior, complete lighting startup, rendering and gameplay are not validated by this suite.

Six malformed/null BYAML fixtures return with original default values; these are separate malformed-input observations. A null first graphics creator produces the same unmapped-read fault after the same ordered boundary interactions. The fault pair compares fault class and boundary trace, not a successful result or full post-fault memory equivalence. No general malformed-input safety or recovery guarantee is claimed.
